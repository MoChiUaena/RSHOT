## 免费接入方式

### 微信公众号

优先试用独立的本机 WeRSS 订阅服务，将获授权读取的公开公众号文章转换为 RSS。候选项目 [rachelos/we-mp-rss](https://github.com/rachelos/we-mp-rss) 主仓库未归档，许可证文件为 MIT；官方文档支持扫码授权、RSS 和授权过期提醒。仍需实测登录方式、账号条件、近期文章和授权有效期。其新版本还支持微信读书模式，不能把不同授权方式当作同一种登录。

常见 [WeWe-RSS](https://github.com/cooderl/wewe-rss) 主仓库已归档，依赖微信读书登录及基础服务；不作为本次默认方案。免费是没有新增采集 API 费用，仍有本机运行和账号维护成本，不保证平台登录状态长期有效。

### X

使用 agent-reach 路由的 `twitter-cli`，从当前用户明确登录的 X 账号低频读取已确认名单，保留帖子 ID、原文地址、文本和发布时间。当前机器尚未安装 Twitter CLI，也未验证登录；首次接入需登录后做小批量读取测试。若接口变动，按工具支持的浏览器后端处理，来源显示失败或暂停，不能用空白结果伪装更新成功。

首期每天北京时间 06:30、18:30 检查，每个 X 账号最多读取 5 条近期公开帖子，不读私信，不发帖、关注或点赞。公众号只刷新经身份确认的本机 feed，读取与全站限额共用受限准入，服务默认高频任务关闭。

## 接入 RSHOT 的实现边界

现有 `x_search` 依赖 SocialData，`mp_account` 依赖极致了，不能把浏览器登录凭据直接填入这两种服务字段。当前本机 `collection.policy` 也不接纳 X 和公众号；公众号原采集任务不会自动套用现有准入数量限制。

因此免费方案需要一个明确的本地只读桥接入口：读取已确认账号的材料后，复用 RSHOT 的统一准入、身份判重和任务排队。对账号清单、数据结构、原文地址和发布时间进行校验，再进入已有模型流程。不得使用普通外部推送绕过限额，也不为读取本机 RSS 全局打开 `ALLOW_PRIVATE_NETWORK_FETCH`。

- 延续近 48 小时窗口、每轮 2 条、每小时 4 条、全站滚动 24 小时 10 条、单源 3 条的初期限额；不增加模型预算。
- 登录、Cookie、订阅数据库、访问令牌和服务配置都放在 Git 仓库外，仅当前用户及所需本地服务可访问。
- 本机订阅管理服务只监听本地地址；日志与公开导出不含授权数据，GitHub Pages 不承载登录状态或采集后台。
- 公开展示继续只含摘要、原文链接和必要的出处信息；不公开转载公众号全文。
- 原论文、预印本、GitHub 项目发布及公众号解读保留各自状态，跨平台转发不增加独立来源数量。
- 登录失效、限流和读取异常进入本地健康记录，停用异常来源，保留上一份有效结果。
- 信源启用之后，复核任务应按实际启用清单检查；新增账号不会被提前写作“已接入”。

## 落地顺序

1. 使用者确认首批名单；不能确认认证主体的账号暂缓。
2. 准备本机隔离的订阅服务与只读 X 工具，使用者登录或扫码，凭据不经过聊天。
3. 小批量验证近期文章、时间、作者、完整贡献描述和可追溯原文。
4. 完成受限桥接、回归测试和私密配置检查后，启用通过验证的来源并更新健康复核清单。
5. 公开快照继续由现有 Windows 发布任务导出与部署。
